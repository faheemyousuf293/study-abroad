# Study Portal – iteration 1: public CMS homepage

Next.js 16 + Payload CMS 3 + PostgreSQL, one codebase. This iteration delivers the homepage, built from
editable blocks, with placeholder brand (**YourBrand**), text and images. Links are placeholders (`#`).

## Run locally

Requirements: Node 20.9+ (22 recommended), pnpm, and either Docker or any local PostgreSQL 14+.

```bash
pnpm install
cp .env.example .env          # then set PAYLOAD_SECRET (openssl rand -hex 32)
pnpm db:up                    # starts Postgres in Docker (skip if you use your own Postgres)
pnpm seed                     # creates the admin user + placeholder homepage content
pnpm dev                      # http://localhost:3000
```

- Site: <http://localhost:3000>
- Admin / CMS: <http://localhost:3000/admin>, log in with `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` from `.env`
  (default `admin@example.com` / `change-me-now`; **change this**).

No domain, Cloudflare or cloud account is needed to run it.

## What you can edit in the admin

| Where | What |
| --- | --- |
| Globals → Site Settings | Brand name, logo, tagline, social links, copyright |
| Globals → Header | Menu items, dropdowns, right-hand links and button |
| Globals → Footer | About text, link columns, legal links |
| Collections → Pages → Home | Homepage blocks: Hero, Core Strengths, Newsletter Signup (reorderable) |
| Collections → Media | Uploaded images (stored in `./media`) |

Pages support drafts and version history. Only published pages are visible to the public.

## Project layout

```
src/payload.config.ts      Payload config (DB, localization, collections, globals)
src/collections/           Users, Media, Pages
src/globals/               SiteSettings, Header, Footer
src/blocks/                Block definitions used by Pages
src/components/            Header, Footer, block renderers
src/app/(frontend)/        Public site (layout, homepage, CSS)
src/app/(payload)/         Admin panel + REST/GraphQL routes (generated by Payload)
src/migrations/            Database migrations (run at startup when RUN_MIGRATIONS=true, for fresh production DBs)
src/seed.ts                Placeholder content
```

## Useful commands

```bash
pnpm typecheck             # TypeScript check
pnpm build && pnpm start   # production build and server
pnpm generate:types        # regenerate src/payload-types.ts after changing collections
pnpm generate:importmap    # regenerate the admin import map after adding custom admin components
npx payload migrate:create <name>   # create a migration after changing the data model
```

## Decisions built in for later iterations

- **One database, one app.** Public CMS and the future partner/student portal share Postgres. Enquiry
  forms will write to a `leads` collection that partners see in the portal.
- **Roles.** `Users.roles` currently only has `admin`. Adding `partner` and `student` means extending
  that list and the access functions.
- **Languages.** English only, but fields are already `localized`, so adding a language is one entry in
  `payload.config.ts` (`localization.locales`).
- **Media storage.** Local disk now; can move to S3 / Cloudflare R2 with a storage adapter.
- **Caching.** Pages render on demand for now. Caching (ISR or Cloudflare) is added with deployment.
